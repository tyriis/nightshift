## §2 Ranked gap list (worst-first)

1. **No consumable artifact for a tester** — the product exists only as a source-built image; `git tag` empty, no registry, no root `README.md` leading to the quickstart · **impact:** an external tester cannot "test it out" at all.
2. **No publish/registry lane** — CI never builds or pushes an image (`ci.yaml` has no docker job); the GHCR name, visibility, and `@sha256` handoff are undecided · **impact:** blocks gap #1 and the QUEUED home-ops deploy — the exact lane #16 also schedules (reconcile ONCE in the iteration shift).
3. **Zero versioning surface** — no git tags, no `CHANGELOG.md`, no locked tag convention · **impact:** "v0.1.0" is currently a field in `package.json`; a tag requires a decision someone must make at tag time.
4. **CI cannot fail a merge** — no `required_status_checks` on `main` (verified live), zero required reviews; CI lacks a docker-build and an e2e job · **impact:** the bar that ACTUALLY ships (suite + deploy-smoke) is enforced by local hooks, not merge machinery — a red fix can land.
5. **E2E not in CI** — `pnpm test:e2e` green locally only; browser reinstall QUEUED (HUMAN) · **impact:** the SvelteKit board is gated by vitest-harness tests only in CI; UI regressions could reach `main`.
6. **Actions tag-pinned, not SHA-pinned** — `actions/*` at `@v4` · **impact:** supply-chain risk concentrated exactly in the release workflows about to be added — fix in the same iteration wave.
7. **No dependency automation** — no Renovate/Dependabot config · **impact:** slow drift; no urgency once a `v0.1.0` tag exists.
8. **Governance-flag gaps** — linear history + conversation-resolution protections unset · **impact:** hygiene, not testability.
9. **Docs shell (polish class)** — CoC/CODEOWNERS/templates/`SECURITY.md` absent · **impact:** none on testability; matters if the repo goes public at tag time.
10. **Observability documentation thin** — stdout log shape undocumented · **impact:** operator-debugging friction at home-ops time; cheap fix later.

## §3 The minimum runnable-beta CUT

**MUST move before the `v0.1.0` tag** (what · why it gates testing · rough effort):

1. **Publish the image once** — decide the GHCR image reference and get ONE tagged image (`ghcr.io/<org>/nightshift:v0.1.0` + its `@sha256` digest) pushed, whether by a manual `docker push` or a minimal CI `docker build`+push on tag. _Why:_ external testing is the entire point of the beta; source-building is homelab-operator-only friction. _Effort:_ ~0.5–1 day — the handoff with #16's publish lane happens ONCE in the iteration shift; do not double-schedule home-ops.
2. **Lock the version surface** — annotated `v0.1.0` tag; record the SemVer/tag/digest mapping in a short note (extend the plan-doc convention per #16's decision-record idea); stub `CHANGELOG.md` with v0.1.0 and the honest known-gaps. _Why:_ "beta" has to BE a tag to be reported against; it also defines rollback ("prior image tag" per `deploy/README.md` upgrade/rollback). _Effort:_ ~half a day, docs-only.
3. **Root `README.md`** — what nightshift is, a 5-line container quickstart linking `deploy/README.md` for the deep surface, spec pointer, license note. _Why:_ without it an external tester never finds the quickstart — the one docs item that gates testing. _Effort:_ ~2–4 h (content largely exists in `deploy/README.md`).
4. **Make CI non-bypassable + add the build gate** — set `required_status_checks` on `main` (the `check` job's rollup, kept minimal) and add a `docker build` arm to `ci.yaml` marked required too (keeps the publish commitment day-one-capable without the push). _Why:_ the tag must be cut from a merge CI could actually stop, and the image arc stays continuously tested. _Effort:_ ~half a day to a day.
5. **Re-run the live bar against the TAGGED image** — `scripts/deploy-smoke.mjs` **24 PASS / 0 FAIL** re-recorded against the image actually published. _Why:_ evidence-licensed claims are the whole brand — never ship a recorded bar that predates the shipped bytes. _Effort:_ ~an hour, mechanical.

**Post-beta (behind the cut):**

- **Renovate/Dependabot config + SHA-pinning policy** — hygiene on an already-shipping artifact.
- **release-please/semantic-release automation** — one human-made tag now buys automation time later.
- **Coverage artifact upload, concurrency groups, path filters, CI e2e job** (incl. the browser reinstall) — quality-of-life; the gates already run locally at full depth.
- **`SECURITY.md`** — needed when the repo goes public; not required to run a beta privately.
- **CoC, CODEOWNERS, issue/PR templates** — docs-polish class, does not gate testing.
- **Provenance/attestation + SBOM, CodeQL, dependency-review-on-PR** — supply-chain depth after the publish lane is exercised.
- **Linear-history + conversation-resolution flags** — governance hygiene.
- **Session dual-rotation, `removeAdditional` flip, CSP, OBS-1, MCP-search re-freeze decision, CLI `search` leg, saved filters/undo, SSE, email** — product-QUEUED (HUMAN) items; they version after the spec-frozen beta.
- **Home-ops HelmRelease + real Pocket ID walkthrough + first-week audit** — already QUEUED (HUMAN); this IS the beta acceptance run and shares only the publish lane (see MUST 1 — reconcile once).
